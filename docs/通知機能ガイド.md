# 通知機能 実装ガイド

## 概要

生駒祭ERP 2026の通知機能は、PWA対応のプッシュ通知システムです。Supabaseのリアルタイム機能を活用し、ユーザーに重要な情報をタイムリーに届けます。

## 主な機能

- ✅ **リアルタイム通知**: Supabase Realtimeによる即座の通知配信
- ✅ **ロールベース配信**: ユーザーロールに基づいた通知の配信制御
- ✅ **プッシュ通知**: PWAによるブラウザ通知（バックグラウンド受信対応）
- ✅ **通知センター**: アプリ内での通知一覧表示と既読管理
- ✅ **カスタマイズ可能**: 通知タイプの追加・拡張が容易

## 使い方

### 1. 通知を送信する

```javascript
// どの画面・コンポーネントからでも使用可能
import { sendNotification } from '@shared/services/sendNotification';

// 基本的な使い方
await sendNotification({
  type: 'info',
  message: 'メンテナンスのお知らせです',
  recipientRoles: 'staff',
});

// 複数ロールに送信
await sendNotification({
  type: 'warning',
  message: 'システムメンテナンスの予定があります',
  recipientRoles: ['admin', 'operator'],
});

// タイトルとディープリンク付き
await sendNotification({
  type: 'error',
  message: '屋台番号105が出店停止しました',
  recipientRoles: 'vendor_manager',
  title: '屋台停止のお知らせ',
  deepLink: '/item5/vendor/105',
});

// メタデータ付き
await sendNotification({
  type: 'inventory_alert',
  message: 'サークルBの在庫が残り20個です',
  recipientRoles: 'inventory_manager',
  metadata: {
    circleId: 'circle_b',
    remainingStock: 20,
  },
});
```

### 2. 通知を受信する

```javascript
// App.jsやルートコンポーネントで購読開始
import { useNotificationSubscription } from '@shared/hooks/useNotificationSubscription';

const App = () => {
  const { user } = useAuth();

  // リアルタイム通知の購読
  useNotificationSubscription(
    user?.id,
    (notification) => {
      console.log('新しい通知:', notification);
      // カスタム処理（例: トースト表示、サウンド再生など）
    },
    { showBrowserNotification: true }
  );

  return <AppNavigator />;
};
```

### 3. 未読通知数を表示する

```javascript
import { NotificationBell } from '@features/notifications/components/NotificationBell';

const Header = () => {
  const { user } = useAuth();
  const [showNotificationCenter, setShowNotificationCenter] = useState(false);

  return (
    <View>
      <NotificationBell
        userId={user?.id}
        onPress={() => setShowNotificationCenter(true)}
      />
    </View>
  );
};
```

## 通知タイプ

### デフォルトタイプ

| タイプID | 説明 | 色 | 優先度 | 自動閉じる |
|---------|------|-----|--------|-----------|
| `info` | 一般情報 | 青 | 低 | 7秒 |
| `success` | 成功 | 緑 | 低 | 5秒 |
| `warning` | 警告 | 橙 | 中 | なし |
| `error` | エラー | 赤 | 高 | なし |
| `vendor_stop` | 屋台停止 | 濃赤 | 高 | なし |
| `schedule_change` | スケジュール変更 | 紫 | 中 | 10秒 |
| `inventory_alert` | 在庫アラート | オレンジ | 中 | なし |
| `user_action` | ユーザーアクション | シアン | 低 | 7秒 |

### カスタムタイプの追加

新しい通知タイプが必要な場合：

1. [notificationType.js](src/features/notifications/constants/notificationType.js) に追加

```javascript
export const NOTIFICATION_TYPES = {
  // 既存のタイプ...
  EMERGENCY: 'emergency', // 新規追加
};

export const NOTIFICATION_TYPE_CONFIG = {
  // 既存の設定...
  [NOTIFICATION_TYPES.EMERGENCY]: {
    displayName: '緊急',
    color: '#DC2626',
    priority: 3,
    autoDismissSeconds: null,
    icon: 'alert',
  },
};
```

2. 使用する

```javascript
await sendNotification({
  type: 'emergency',
  message: '緊急事態が発生しました',
  recipientRoles: ['admin', 'operator'],
});
```

## データベース設計

### notifications テーブル

```sql
CREATE TABLE notifications (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  type TEXT NOT NULL,
  title TEXT,
  message TEXT NOT NULL,
  recipient_roles JSONB NOT NULL,
  target_user_ids JSONB NOT NULL,
  sent_by UUID NOT NULL REFERENCES users(id),
  deep_link TEXT,
  metadata JSONB DEFAULT '{}',
  status TEXT NOT NULL DEFAULT 'pending',
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  expires_at TIMESTAMP WITH TIME ZONE NOT NULL
);

CREATE INDEX idx_notifications_target_users ON notifications USING GIN (target_user_ids);
CREATE INDEX idx_notifications_created_at ON notifications(created_at DESC);
CREATE INDEX idx_notifications_expires_at ON notifications(expires_at);
```

### notification_reads テーブル

```sql
CREATE TABLE notification_reads (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  notification_id UUID NOT NULL REFERENCES notifications(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  read_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(notification_id, user_id)
);

CREATE INDEX idx_notification_reads_user ON notification_reads(user_id);
CREATE INDEX idx_notification_reads_notification ON notification_reads(notification_id);
```

### notification_types テーブル（オプション）

```sql
CREATE TABLE notification_types (
  id TEXT PRIMARY KEY,
  display_name TEXT NOT NULL,
  color TEXT NOT NULL,
  priority INTEGER NOT NULL DEFAULT 1,
  auto_dismiss_seconds INTEGER,
  icon TEXT,
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

## Service Workerの登録

[public/index.html](public/index.html) で Service Worker を登録：

```html
<script>
  if ('serviceWorker' in navigator) {
    window.addEventListener('load', () => {
      navigator.serviceWorker
        .register('/notification-service-worker.js')
        .then((registration) => {
          console.log('Service Worker registered:', registration);
        })
        .catch((error) => {
          console.error('Service Worker registration failed:', error);
        });
    });
  }
</script>
```

## トラブルシューティング

### 通知が届かない

1. ブラウザの通知権限を確認
2. Service Workerが正しく登録されているか確認
3. Supabase Realtimeの接続状態を確認

```javascript
// デバッグ用
console.log('Notification permission:', Notification.permission);
navigator.serviceWorker.getRegistration().then(reg => {
  console.log('Service Worker:', reg);
});
```

### 未読数が更新されない

- `useUnreadCount`フックの更新間隔を確認（デフォルト: 30秒）
- 手動で`refetch()`を呼び出して更新

```javascript
const { unreadCount, refetch } = useUnreadCount(userId);

// 手動更新
useEffect(() => {
  refetch();
}, [someEvent]);
```

### 期限切れ通知が削除されない

自動クリーンアップを開始：

```javascript
import { startAutoCleanup } from '@shared/services/notificationManager';

// 60分ごとにクリーンアップ
const stopCleanup = startAutoCleanup(60);

// クリーンアップ停止
return () => stopCleanup();
```

## ベストプラクティス

### 1. 適切なロールの指定

```javascript
await sendNotification({
  type: 'info',
  message: 'スケジュール更新',

});

// ❌ 悪い例：全員に通知
await sendNotification({
  type: 'info',
  message: '全員に通知',
  recipientRoles: ['staff', 'manager', 'admin'],
});
```

### 2. 適切な通知タイプの使用

```javascript
// ✅ 良い例：エラーはerrorタイプ
await sendNotification({
  type: 'error',
  message: 'システムエラーが発生しました',
  recipientRoles: 'admin',
});

// ❌ 悪い例：エラーをinfoタイプで送信
await sendNotification({
  type: 'info',
  message: 'システムエラーが発生しました',
  recipientRoles: 'admin',
});
```

### 3. ディープリンクの活用

```javascript
// ✅ 良い例：詳細画面へのリンク付き
await sendNotification({
  type: 'warning',
  message: '在庫が少なくなっています',
  recipientRoles: 'inventory_manager',
  deepLink: '/item3/inventory/details',
});
```

## セキュリティ

- 通知送信時に自動的に権限を検証
- Supabaseの RLS（Row Level Security）で保護
- ユーザーは自分に関連する通知のみ受け取れる

## パフォーマンス

- 未読数は30秒ごとに自動更新（カスタマイズ可能）
- 期限切れ通知は自動削除（デフォルト: 24時間後）
- 通知リストは仮想化により大量のデータでも高速表示
