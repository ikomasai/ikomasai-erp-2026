# プロジェクト仕様書 — 厚生部呼び出しシステム

最終更新日: 2026/03/17

---

## 1. 概要

### 1.1 目的

厚生部呼び出しシステムは、来場者または部員が傷病者対応を厚生部へ依頼し、厚生部側が対応状況を一覧で管理できる機能である。

現行システムでは、呼び出し作成時に問診形式で必要情報を収集し、厚生部側は一覧画面から救護者設定と対応終了を行う。

### 1.2 実装方針

- フロントエンド: React Native (Expo)
- バックエンド: Supabase
- リアルタイム更新: `item2_calls` の Supabase Realtime 購読
- 通知: ERP 通知基盤 (`dispatch-notification` Edge Function)
- 実装ディレクトリ: `src/features/item2/`

### 1.3 現行スコープ

現行実装に含むもの:
- 呼び出し作成
- 問診分岐フォーム
- 呼び出し履歴 / 対応一覧表示
- 救護者設定
- 対応終了
- 厚生部ロール向け通知

現行実装に含まないもの:
- チャット
- 既読 / 未読
- 画像送信
- 通話

---

## 2. 対象ユーザー

### 2.1 一般ユーザー

- 自分または他者の体調不良・怪我について厚生部を呼び出す
- 自分が作成した呼び出し履歴を確認する

### 2.2 厚生部ユーザー

- すべての呼び出しを対応一覧で確認する
- 救護者を設定する
- 呼び出しを対応終了に変更する

### 2.3 管理者

- 厚生部ユーザーと同等に対応一覧へアクセスできる

## 4. 機能要件

## 4.1 呼び出し作成

### 4.1.1 入力方式

- 一問一答形式で表示する
- 単一選択項目はラジオボタンで選択する
- 複数選択項目はチェックボックスで選択する
- テキスト入力項目は自由記述とする
- `場所` は必須入力
- `場所以外の自由記述` は任意入力

### 4.1.2 初期質問

1. `緊急度を選択してください`
   - `不急`
   - `緊急`
2. `あなたは傷病者本人ですか？`
   - `はい`
   - `いいえ`

### 4.1.3 本人ではない場合の質問

3. `傷病者の意識はありますか`
   - `ある`
   - `反応が弱い`
   - `ない`
4. `傷病者は呼吸していますか`
   - `している`
   - `していない`
   - `わからない`

補足:
- `意識 = 反応が弱い / ない` の場合、後続の状態分類質問は表示しない
- この場合は `場所` を入力すれば作成可能

### 4.1.4 本人の場合の質問

3. `文字の入力や選択は可能ですか？`
   - `可能`
   - `不可能`

分岐:
- `不可能` の場合は `場所` のみ入力させる
- `可能` の場合は次の質問へ進む

4. `あなたは立つ/歩くことができますか`
   - `どちらもできる`
   - `立つことはできるが歩くことは厳しい`
   - `どちらもできない`

### 4.1.5 状態分類質問

状態分類質問は、以下の条件を満たした場合のみ表示する。

- 本人ではない かつ 意識が `ある`
- または 本人 かつ 文字入力・選択が `可能`

質問文:
- 本人の場合: `あなたはどういった状態ですか？`
- 本人ではない場合: `傷病者はどういった状態ですか？`

選択肢:
- `軽い怪我(擦り傷や打撲など)`
- `中程度の怪我(切り傷や捻挫など)`
- `重度の怪我(転落や骨折など)`
- `体調不良`
- `その他(様子がおかしい/震えているなど)`

### 4.1.6 状態分類ごとの追加質問

#### 軽い怪我 / 中程度の怪我 / 重度の怪我

- まず `出血はありますか？` を質問する
  - `ある`
  - `ない`
- `ある` 場合
  - `どこから出血していますか？` 自由記述
  - `どのくらい出血していますか？` 自由記述
- `ない` 場合
  - `あなたは/傷病者はどこを痛がっていますか？` 自由記述
  - `腫れや内出血等はありますか？`
    - `腫れている`
    - `内出血がある`
    - `わからない`
    - `その他`
  - `その他` 選択時のみ補足自由記述を表示

#### 体調不良

質問文:
- 本人の場合: `あなたはどういう状態ですか？`
- 本人ではない場合: `傷病者はどういう状態ですか？`

複数選択肢:
- `発熱`
- `倦怠感`
- `めまい`
- `頭痛`
- `吐き気`
- `腹痛`
- `手足のしびれ`
- `吐血`
- `その他`

補足:
- `その他` 選択時のみ補足自由記述を表示
- チェックボックスは枠線ベースで表示し、選択時は中央に小さいチェックを出す

#### その他

- `その他の状態を入力してください` 自由記述

### 4.1.7 場所入力

- すべての分岐の最後に `場所を入力してください` を表示する
- プレースホルダ:
  - `例: 11月ホール 2階 学友会連合会室前`

### 4.1.8 作成時の保存内容

呼び出し作成時に以下を保存する。

- 呼び出し者ID
- 呼び出し者名
- 呼び出し種別
- 傷病者本人かどうか
- 要約文 (`detail`)
- 場所
- 問診回答 JSON (`assessment_answers`)

### 4.1.9 要約文の生成

`detail` には、入力内容から生成した一問一答形式の要約文を保存する。

例:

```text
傷病者: 本人ではない
意識: あり
呼吸: なし
状態: 体調不良
症状: 発熱、倦怠感
```

## 4.2 呼び出し一覧 / 履歴表示

### 4.2.1 一般ユーザーの履歴

- ログイン中ユーザーが作成した呼び出しのみ表示する
- タブ名は `履歴`

### 4.2.2 厚生部側の対応一覧

- すべての呼び出しを表示する
- 初期並び順は以下:
  - `未対応`
  - `対応中`
  - `対応終了`
- 同一ステータス内では `created_at` の降順

### 4.2.3 対応一覧の絞り込み

#### ステータス絞り込み

- `すべて`
- `未対応`
- `対応中`
- `対応終了`

#### 種別絞り込み

- `すべて`
- `緊急`
- `不急`

### 4.2.4 一覧カード表示項目

- 呼び出し種別 (`緊急` / `不急`)
- ステータスバッジ
- 要約文
- 場所
- 呼び出し者名
- 呼び出し者ロール
- 作成時刻
- 救護者名

呼び出し者ロールは、`user_roles` と `roles` を参照して表示する。
ロールが存在しない場合は `なし` と表示する。

---

## 4.3 救護者設定

### 4.3.1 操作権限

- 厚生部ロールまたは管理者ロールを持つユーザーのみ実行可能

### 4.3.2 設定方法

- 一覧カードの `救護者設定` または `担当者設定` ボタンからモーダルを開く
- 複数人選択可能
- モーダルで `確定` を押した時点で保存する
- `戻る` を押した場合は保存しない

### 4.3.3 モーダル仕様

- モーダルタイトル:
  - 緊急: `救護者を選択`
  - 不急: `担当者を選択`
- 候補ユーザー: `厚生部` および `管理者` ロールを持つユーザー
- ユーザー検索:
  - `名前で検索` 入力欄を持つ
  - 入力文字列に応じて候補を即時絞り込みする
  - 一致なしの場合は `該当する名前がありません。` を表示する

### 4.3.4 ステータス自動変更

救護者設定時のステータス遷移は以下とする。

- 現在 `未対応` かつ 救護者が1人以上設定された場合: `対応中` に変更
- 現在 `対応中` の場合: そのまま維持
- 現在 `対応終了` の場合: そのまま維持

### 4.3.5 監査ログ

救護者更新時は `item2_audit_logs` に `call_assignees_updated` を記録する。

---

## 4.4 対応終了

### 4.4.1 操作権限

- 厚生部ロールまたは管理者ロールを持つユーザーのみ実行可能

### 4.4.2 実行条件

- `対応終了` ボタンは、未終了の呼び出しに対して表示する

### 4.4.3 確認 UI

- `対応終了` 押下時は画面内モーダルを表示する
- 表示文言:
  - `確認`
  - `対応を終了しますか？`
- ボタン:
  - `いいえ`
  - `はい`

### 4.4.4 更新内容

- ステータスを `resolved` に更新
- `resolved_at` を現在時刻で保存
- `resolved_by` に実行者IDを保存

---

## 4.5 通知

### 4.5.1 呼び出し作成通知

呼び出し作成成功後、厚生部ロール所持者へ ERP 通知を送信する。

#### 宛先

- `厚生部` ロール所持者

#### 通知タイトル

- `厚生部呼び出し`

#### 通知本文

- `{呼び出し者名}さんから{緊急/不急}の呼び出しが作成されました。場所: {場所}`

#### metadata

- `type: item2_call_created`
- `call_id`
- `call_type`
- `status`
- `requester_name`
- `location_text`

### 4.5.2 通知失敗時の扱い

- 通知送信に失敗しても、呼び出し作成自体は成功扱いとする
- 失敗内容はクライアントコンソールに出力する

## 6. データベース設計

## 6.1 使用テーブル

現行の `item2` で使用する主テーブル:
- `item2_calls`
- `item2_audit_logs`

補助参照テーブル:
- `user_profiles`
- `roles`
- `user_roles`

チャット関連テーブル:
- `item2_chat_rooms`
- `item2_chat_messages`
- `item2_chat_read_states`

上記チャット関連テーブルは `20260313_drop_item2_chat_tables.sql` で削除対象になっており、現行機能では使用しない。

### 6.2 item2_calls

| カラム名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| id | uuid | Yes | 呼び出しID |
| requester_user_id | uuid | Yes | 呼び出し者ユーザーID |
| requester_name | text | Yes | 呼び出し者表示名 |
| requester_relation | text | No | `self` / `other` |
| call_type | text | Yes | `emergency` / `non_urgent` |
| purpose | text | No | 状態分類ラベル |
| detail | text | No | 問診要約文 |
| location_text | text | Yes | 場所 |
| status | text | Yes | `unhandled` / `in_progress` / `resolved` |
| assigned_to | uuid[] | Yes | 救護者ユーザーID一覧 |
| assessment_answers | jsonb | No | 問診回答 JSON |
| resolved_at | timestamptz | No | 対応終了日時 |
| resolved_by | uuid | No | 対応終了実行者 |
| created_at | timestamptz | Yes | 作成日時 |
| updated_at | timestamptz | Yes | 更新日時 |

### 6.3 assessment_answers

`assessment_answers` には、フォームの回答一式を JSON で保存する。

主な格納例:
- `callType`
- `requesterRelation`
- `selfCanUseText`
- `consciousness`
- `breathing`
- `mobility`
- `conditionCategory`
- `symptoms`
- `locationText`
- `summaryText`

### 6.4 item2_audit_logs

救護者更新時の監査ログを保存する。

主なカラム:
- `event_type`
- `call_id`
- `actor_id`
- `old_value`
- `new_value`
- `created_at`

## 10. 非機能要件

### 10.1 操作性

- モバイル端末で操作可能であること
- 選択肢は大きめのタップ領域を持つこと
- 入力フローは上から順に自然に進めること

### 10.2 保守性

- 問診の詳細回答は `assessment_answers` に JSON 保存し、将来の質問追加で DB 変更を最小限にする
- 一覧表示に必要な派生情報はクライアント側で整形してよい

### 10.3 障害許容

- 通知送信失敗で呼び出し作成を失敗させない
- 一部 migration 未反映環境でも最小限の呼び出し登録を継続できるようにする
