# プロジェクト仕様書_アクセス権限制御

最終更新日: 2026-03-31
対象実装: `src/features/item7`

---

## 1. 目的

ロール（部署・役職）ごとの画面アクセス権限、およびユーザーとロールの紐付けを、GUIで確認・編集できる管理画面を提供する。
`roles` テーブルの `permissions.screens` と `user_roles` テーブルを、SQLを直接操作せずに管理可能にする。

## 3. アクセス権限

### 3.1 本画面へのアクセス条件

以下のいずれかのロールを持つユーザーのみアクセス可能:

- **システム部**
- **管理者**

`permissionService.js` の `canAccessScreen('item7')` で判定。`roles.permissions.screens` に `"item7"` が含まれるロールを持つユーザーのみアクセス可能。

### 3.2 ナビゲーション設定

| 設定箇所 | 値 |
|---|---|
| `DrawerNavigator.jsx` の `Drawer.Screen options.title` | `'アクセス権限制御'`（ブラウザタブ名） |
| `CustomDrawerContent.jsx` の `ITEM_LABELS[7]` | `'アクセス権限制御'`（サイドバー表示名） |

## 4. データ設計

### 4.1 使用テーブル

| テーブル | RLS | 用途 |
|---|---|---|
| `roles` | ON（UPDATE/INSERT/DELETE は `is_permission_manager()` で制限） | ロール定義・permissions管理 |
| `user_roles` | OFF | ユーザーとロールの紐付け |
| `user_profiles` | OFF | ユーザー名・所属の表示 |

### 4.2 RLSポリシー（roles テーブル）

```sql
-- SECURITY DEFINER 関数: 管理者またはシステム部かを判定
CREATE OR REPLACE FUNCTION public.is_permission_manager()
RETURNS boolean LANGUAGE plpgsql SECURITY DEFINER AS $$
BEGIN
  RETURN EXISTS (
    SELECT 1 FROM user_roles ur
    JOIN roles r ON r.id = ur.role_id
    WHERE ur.user_id = auth.uid()
      AND r.name IN ('管理者', 'システム部')
  );
END;
$$;

-- SELECT: 全認証済みユーザーが参照可能
-- UPDATE / INSERT / DELETE: is_permission_manager() が true のユーザーのみ
```

### 4.3 permissions カラム構造（JSONB）

```json
{
  "screens": ["企画・屋台一覧", "item2", "item3", ...]
}
```

- `screens` 配列のみ本機能で管理する
- 例外: 企画管理部のみ `features` キーも存在するが、本機能のスコープ外
- 更新時は `features` 等の既存キーを消失させないよう `{ ...existingPermissions, screens: newScreens }` でマージする

## 5. 画面仕様

### 5.1 全体レイアウト

```
┌──────────────────────────────────────────────────────────────┐
│  アクセス権限制御                                               │
│  ┌────────────┬────────────┬─────────────┐                   │
│  │  ロール別   │  項目別    │  ユーザ管理  │  ← タブ切替       │
│  └────────────┴────────────┴─────────────┘                   │
│  （タブ内容はそれぞれのセクション参照）                           │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 タブ共通仕様

- **タブ再クリック**: 現在アクティブなタブを再度押すと、そのタブの選択状態がリセットされ一覧に戻る
- **モバイル（< 768px）**: リスト → 詳細の段階的表示。戻るボタン（← 一覧）で前のパネルに戻る
- **PC（>= 768px）**: パネルを横並び表示

---

### 5.3 ロール別タブ

#### 左パネル: ロール一覧

- 全ロールを `display_name` で表示（`display_name` がない場合は `name`）
- 上部に検索バー（テキスト部分一致フィルター）と「+ 新規」ボタン（横並び）
- 選択中ロールはプライマリカラーでハイライト
- 各ロールの右側に現在のアクセス可能項目数バッジ（固定幅）
- 各ロールの右端に削除ボタン「×」（固定幅）
  - **保護対象ロール**（管理者・システム部）は削除ボタン非表示

#### 右パネル: 項目チェックリスト

- 選択ロールの全16項目をチェックボックスで一覧表示
- チェックON = `permissions.screens` にpermission名が含まれる
- **PROTECTED_PERMISSIONS** に該当する組み合わせはグレーアウト + `(変更不可)` 表示
- 変更がある場合のみ「保存」「リセット」ボタンが活性化
- 保存時: 確認モーダル → 完了モーダル（または失敗モーダル）

#### ロール作成フロー

「+ 新規」ボタン → 専用フォーム画面（`RoleCreateScreen`）に遷移:

| フィールド | 種別 | 備考 |
|---|---|---|
| ロール名 | 必須テキスト | `name` と `display_name` の両方に同値を使用 |
| ロール説明 | 任意テキストエリア | `description` カラムに保存 |
| 初期アクセス権限 | チェックリスト | 作成時の初期 `permissions.screens` |

- 重複ロール名の場合はエラーモーダル表示（`23505` constraint違反検出）
- 成功時は完了モーダル → 閉じると一覧に戻る

#### ロール削除フロー

「×」ボタン押下:
1. ユーザー数を事前取得
2. 確認モーダル（ユーザー数 > 0 の場合は影響ユーザー数を明示）
3. 承認 → `user_roles` から該当ロールの紐付けを先に削除 → `roles` から削除
4. 完了モーダル表示

---

### 5.4 項目別タブ

#### 左パネル: 項目一覧

- 全16項目をUIラベルで表示
- 上部に検索バー（テキスト部分一致フィルター）
- 各項目の右側にアクセス可能なロール数バッジ

#### 右パネル: ロールチェックリスト

- 選択項目にアクセスできるロールをチェックボックスで一覧表示
- **「全団体アクセス可能」**: 全ロールをON
- **「全団体解除」**: 全ロールをOFF（PROTECTED_PERMISSIONS 対象は除く）
- 保存時: 変更のあったロールを一括更新（`updateMultipleRoleScreens`）

---

### 5.5 ユーザ管理タブ

3カラムレイアウト（PC）/ 3段階の段階的表示（モバイル）。

```
PC:
┌──────────────┬──────────────┬─────────────────────────┐
│ ロール一覧    │ ユーザー一覧  │ ロールチェックリスト      │
│ （左パネル）  │ （中央パネル）│ （右パネル）              │
│              │              │                         │
│ [検索]        │ {ロール名}   │ {ユーザー名} のロール     │
│              │ {ユーザー数}  │ ─────────────────────── │
│ ロールA    5 │ [検索]        │ ☑ 管理者                │
│ ロールB    3 │              │ ☑ 企画管理部             │
│ ...          │ 山田 太郎     │ ☐ 会計部                │
│              │ 田中 花子 ◀  │ ...                     │
│ ────────────  │ ...          │             [保存][リセット] │
│ ロール未所持  │              │                         │
│         2人  │              │                         │
└──────────────┴──────────────┴─────────────────────────┘
```

#### 左パネル: ロール一覧

- 全ロールを表示（`RoleListPanel` を再利用、作成/削除ボタン非表示）
- バッジにはアクセス項目数ではなく**ユーザー数**を表示
- 検索バーでロールを絞り込み可能
- **「ロール未所持」セクション**: ロール一覧とは独立した別枠ボックスとして最下部に配置
  - ロールを1件も持たないユーザーの人数を表示
  - タッチするとそのユーザー一覧を中央パネルに表示

#### 中央パネル: ユーザー一覧

- 選択ロールを持つユーザー一覧（名前 + 所属）
- 上部にヘッダー（ロール名 + ユーザー数）と検索バー
- 選択中ユーザーはハイライト

#### 右パネル: ロールチェックリスト

- 選択ユーザーが持つロールをチェックボックスで表示（全ロール一覧）
- チェックON = `user_roles` テーブルに紐付けが存在する
- 保存時: 確認モーダル → `user_roles` の差分をINSERT/DELETE
- 保存後:
  - 中央パネルのユーザー一覧を再取得（ロールが変わりリストから外れる場合あり）
  - ロールユーザー数バッジを再計算
  - 「ロール未所持」カウントを再計算

#### 機密ロール警告（SENSITIVE_ROLES）

**管理者** または **システム部** ロールを付与・解除しようとした場合に確認モーダルを表示:

| 操作 | モーダルメッセージ |
|---|---|
| 付与 | 「このロールを付与するとアクセス権限制御画面にアクセスでき、全ロールの管理が可能になります」 |
| 解除 | 「このロールを解除するとアクセス権限制御画面にアクセスできなくなります」 |

- 承諾すれば通常通り付け外し可能（拘束力なし）

---

### 5.6 モーダル一覧

すべてのダイアログは `window.confirm` / `window.alert` ではなく React Native `Modal` で実装。

| モーダル | 種別 | タイミング |
|---|---|---|
| 保存確認 | confirm（キャンセルあり） | 保存ボタン押下時 |
| 更新完了 | alert（閉じるのみ） | 保存成功後 |
| 更新エラー | alert（閉じるのみ） | 保存失敗時 |
| ロール削除確認 | confirm（削除するボタンは赤色） | 削除ボタン押下後、ユーザー数確認後 |
| 削除完了 | alert | 削除成功後 |
| 削除エラー | alert | 削除失敗時 |
| 作成エラー | alert | ロール作成失敗時（重複名など） |
| 機密ロール警告 | confirm | 管理者/システム部ロールの付与・解除時 |

## 6. セーフガード

### 6.1 ロックアウト防止（PROTECTED_PERMISSIONS）

```javascript
const PROTECTED_PERMISSIONS = [
  { roleName: '管理者',     permissionName: 'item7' },
  { roleName: 'システム部', permissionName: 'item7' },
];
```

- 上記組み合わせはUI上でdisabled + `(変更不可)` 表示
- ロール別・項目別タブの両方で適用

### 6.2 機密ロール警告（SENSITIVE_ROLES）

```javascript
const SENSITIVE_ROLES = [
  { roleName: '管理者',   addMessage: '...', removeMessage: '...' },
  { roleName: 'システム部', addMessage: '...', removeMessage: '...' },
];
```

- ユーザ管理タブでのロール付け外し時に確認モーダルを表示（拘束力なし）

### 6.3 保護対象ロールの削除防止

`removeRole()` 内でも PROTECTED_PERMISSIONS を確認し、保護対象ロールはサービス層レベルで削除を拒否する。

## 10. 既知の制約事項

### 10.1 permissions.features は対象外

`permissions.features`（画面内機能レベルの権限）は本機能では編集しない。現在 `features` を使用しているのは `企画管理部` の `item12` のみ。将来的に features の管理UIが必要になった場合は別途対応する。

### 10.2 permission名の混在

`permissions.screens` に格納される名前が日本語（`企画・屋台一覧`、`落とし物検索` など）と英語（`item2`、`item12` など）で混在している。本機能ではこの混在を維持し、既存のアクセス制御ロジックとの互換性を保つ。
