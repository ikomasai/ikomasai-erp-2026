## 📋 実装した主要機能

### 通知送信（sendNotification）

```javascript
import { sendNotification } from '@shared/services/sendNotification';

// シンプルな使い方
await sendNotification({
  type: 'info',
  message: 'メッセージ本文',
  recipientRoles: 'staff',
});

// 詳細な設定
await sendNotification({
  type: 'warning',
  message: '屋台番号105が停止しました',
  recipientRoles: ['vendor_manager', 'admin'],
  title: '屋台停止のお知らせ',
  deepLink: '/item5/vendor/105',
  metadata: { vendorId: 105 },
});
```

### 通知タイプ

8種類のデフォルト通知タイプを実装：
- `info` - 一般情報（青色、7秒で自動閉じる）
- `success` - 成功（緑色、5秒で自動閉じる）
- `warning` - 警告（橙色、自動で閉じない）
- `error` - エラー（赤色、自動で閉じない）
- `vendor_stop` - 屋台停止（濃赤色、自動で閉じない）
- `schedule_change` - スケジュール変更（紫色、10秒で自動閉じる）
- `inventory_alert` - 在庫アラート（オレンジ色、自動で閉じない）
- `user_action` - ユーザーアクション（シアン色、7秒で自動閉じる）

### ユーザーロール

10種類のロールを定義：
- `admin` - システム管理者
- `operator` - オペレーター
- `staff` - スタッフ
- `vendor_manager` - 屋台担当マネージャー
- `inventory_manager` - 在庫管理者
- `accountant` - 会計担当者
- `schedule_manager` - スケジュール管理者
- `circle_leader` - サークル責任者
- `circle_member` - サークルメンバー
- `manager` - 総合マネージャー

### リアルタイム通知

Supabase Realtimeを使用したリアルタイム通知配信：
- 通知がデータベースに挿入されると即座にユーザーに配信
- バックグラウンドでの通知受信にも対応
- ブラウザ通知（OS通知）の表示

### 既読管理

- 通知の既読・未読状態を管理
- 未読数のリアルタイム表示
- 一括既読機能

## 🔧 必要なデータベース設定

実装を動作させるには、以下のSupabaseテーブルが必要です：

### 1. notifications テーブル

```sql
CREATE TABLE notifications (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  type TEXT NOT NULL,
  title TEXT,
  message TEXT NOT NULL,
  recipient_roles JSONB NOT NULL,
  target_user_ids JSONB NOT NULL,
  sent_by UUID NOT NULL REFERENCES users(id),
  deep_link TEXT,
  metadata JSONB DEFAULT '{}',
  status TEXT NOT NULL DEFAULT 'pending',
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  expires_at TIMESTAMP WITH TIME ZONE NOT NULL
);

CREATE INDEX idx_notifications_target_users ON notifications USING GIN (target_user_ids);
CREATE INDEX idx_notifications_created_at ON notifications(created_at DESC);
CREATE INDEX idx_notifications_expires_at ON notifications(expires_at);
```

### 2. notification_reads テーブル

```sql
CREATE TABLE notification_reads (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  notification_id UUID NOT NULL REFERENCES notifications(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  read_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(notification_id, user_id)
);

CREATE INDEX idx_notification_reads_user ON notification_reads(user_id);
CREATE INDEX idx_notification_reads_notification ON notification_reads(notification_id);
```

### 3. users テーブルの更新

既存の`users`テーブルに`roles`カラムを追加（まだない場合）：

```sql
ALTER TABLE users ADD COLUMN IF NOT EXISTS roles JSONB DEFAULT '[]';
CREATE INDEX idx_users_roles ON users USING GIN (roles);
```

### 2. Service Workerの登録

`public/index.html`に以下を追加：

```html
<script>
  if ('serviceWorker' in navigator) {
    window.addEventListener('load', () => {
      navigator.serviceWorker
        .register('/notification-service-worker.js')
        .then((registration) => {
          console.log('Service Worker registered:', registration);
        })
        .catch((error) => {
          console.error('Service Worker registration failed:', error);
        });
    });
  }
</script>
```

### 3. 通知システムの初期化

`App.js`またはルートコンポーネントで初期化：

```javascript
import { initializeNotificationSystem } from './src/shared/services/notificationManager';
import { useNotificationSubscription } from './src/shared/hooks/useNotificationSubscription';

const App = () => {
  const { user } = useAuth();

  // 初期化
  useEffect(() => {
    if (user?.id) {
      initializeNotificationSystem(user.id);
    }
  }, [user]);

  // リアルタイム購読
  useNotificationSubscription(
    user?.id,
    (notification) => {
      console.log('新しい通知:', notification);
    },
    { showBrowserNotification: true }
  );

  return <AppNavigator />;
};
```

### 4. ヘッダーに通知ベルを追加

## ⚠️ 注意事項

1. **プッシュ通知の権限**: 初回アクセス時にブラウザの通知権限をリクエストする必要があります
2. **HTTPS必須**: プッシュ通知はHTTPS環境でのみ動作します
3. **ブラウザ対応**: プッシュ通知は一部のブラウザでサポートされていません
4. **パフォーマンス**: 未読数は30秒ごとに更新されます（カスタマイズ可能）
5. **データ保持**: 通知はデフォルトで24時間後に自動削除されます
