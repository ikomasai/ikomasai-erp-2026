# プロジェクト仕様書 - 設定画面の統合とパスワード変更機能の追加

最終更新日: 2026/03/26

---

## 概要

現在サイドバーの「設定」セクションにはテーマ設定のみが存在し、パスワード変更は初回ログイン時の推奨モーダルでしかアクセスできない。本仕様では以下を実現する。

1. **「設定」画面を新設**し、設定系の機能を一箇所に集約する
2. 設定画面から**任意タイミングでパスワード変更**を行えるようにする
3. 既存のテーマ設定を設定画面内のセクションとして統合する

---

## 現状の課題

| 課題 | 詳細 |
|------|------|
| パスワード変更手段が限定的 | 初回ログイン時にスキップすると、以降パスワードを変更する導線がない |
| 設定項目が分散している | テーマ設定は独立画面、通知送信（管理者）も設定セクションに混在 |
| 拡張性が低い | 設定項目を追加するたびにサイドバーに項目が増えてしまう |

---

## 機能要件

### 基本方針

- サイドバーの「設定」セクションを**1つの「設定」画面へのリンク**に変更する
- 設定画面は**1ページにセクションが縦並びで表示される**（別画面には遷移しない）
- 各セクションに操作UIをそのまま配置し、保存ボタンもセクション内に置く
- 初回ログイン時のパスワード変更推奨モーダルは**そのまま維持**する

### 設定画面の構成

| セクション | 内容 | 対象ユーザー | 備考 |
|-----------|------|-------------|------|
| アカウント | パスワード変更フォーム（3入力 + 保存ボタン） | 全ユーザー | 新規追加 |
| 表示 | テーマ選択UI | 全ユーザー | UIコンポーネントを新規作成（既存 `SettingsThemeScreen` からの流用不可） |
| 管理者 | 通知送信UI | 管理者のみ | UIコンポーネントを新規作成（既存 `AdminTestNotificationScreen` からの流用不可） |

> **注意:** テーマ設定・管理者通知送信は既存の独立画面（`SettingsThemeScreen` / `AdminTestNotificationScreen`）を流用するのではなく、設定画面のセクションとして**UIを再定義して新規作成**する。ロジック（サービス・フック）は既存のものを再利用、新規ファイルに移設する。

## 画面設計

### 1. 設定画面（SettingsScreen）— 新規作成

**アクセス経路:**
- サイドバー「設定」→「設定」をタップ

**デザイン（PC/スマホ共通）:**
```
┌─────────────────────────────────────┐
│  ⚙️ 設定                            │
├─────────────────────────────────────┤
│  ▼ アカウント ─────────────────────  │
│                                     │
│  現在のパスワード                    │
│  ┌───────────────────────────────┐  │
│  │  ●●●●●●●●                     │  │
│  └───────────────────────────────┘  │
│  ⚠️ エラーメッセージ                │
│                                     │
│  新しいパスワード（8文字以上）       │
│  ┌───────────────────────────────┐  │
│  │  ●●●●●●●●                     │  │
│  └───────────────────────────────┘  │
│  ⚠️ エラーメッセージ                │
│                                     │
│  新しいパスワード（確認用）          │
│  ┌───────────────────────────────┐  │
│  │  ●●●●●●●●                     │  │
│  └───────────────────────────────┘  │
│  ⚠️ エラーメッセージ                │
│                                     │
│  ┌───────────────────────────────┐  │
│  │  パスワードを変更する          │  │
│  └───────────────────────────────┘  │
│                                     │
│  ▼ 表示 ───────────────────────────  │
│                                     │
│  ┌───────────────┐  ┌─────────────┐ │
│  │ ☀️ ライト [✓] │  │ 🌙 ダーク   │ │
│  └───────────────┘  └─────────────┘ │
│  ┌───────────────┐  ┌─────────────┐ │
│  │ 🌸 ゆるふわ   │  │ 💻 サイバー │ │
│  └───────────────┘  └─────────────┘ │
│  （変更は即時反映）                  │
│                                     │
│  ▼ 管理者 ─────────────────────── ※ │
│  （管理者ユーザーのみ表示）          │
│  ・・・通知送信UI・・・             │
│                                     │
└─────────────────────────────────────┘
```

**動作:**
- 設定画面は**1つのScrollView**で全セクションを縦スクロール表示する（別画面への遷移なし）
- 「管理者」セクションは `isAdmin` の場合のみ表示
- パスワード変更成功時は**設定画面内に成功メッセージをインライン表示**し、フォームをリセット
  - **初回ログインフローとの違い**: 初回ログインフローではJimuShift画面に遷移するが、設定画面からの変更時は画面遷移しない
- テーマ選択は既存の `SettingsThemeScreen` と同等の即時反映動作
- `password_changed_at` の更新は既存の `passwordService.js` をそのまま使用

**パスワードセクションの入力フィールド:**

| フィールド | 必須 | バリデーション | placeholder |
|-----------|------|---------------|-------------|
| 現在のパスワード | はい | 空欄チェック | "現在のパスワードを入力" |
| 新しいパスワード | はい | 空欄チェック、8文字以上、現在と異なること | "新しいパスワードを入力（8文字以上）" |
| 新しいパスワード（確認用） | はい | 空欄チェック、新パスワードと一致 | "もう一度入力してください" |

### 2. サイドバーの変更

**変更前:**
```
各種項目タブ
├──企画・屋台検索
├──当日部員シフト
├──迷子検索
├── テーマ設定
└── 🔔 通知送信（管理者）（管理者のみ）
```

**変更後:**
```
各種項目タブ
├──企画・屋台検索
├──当日部員シフト
├──迷子検索
:
└── 設定（→ 設定画面へ遷移）
```

設定画面の内部構成（1ページにセクションが縦並び）:
```
設定画面（ScrollView）
├── アカウント
│   └── パスワード変更フォーム（3入力 + 保存ボタン）
├── 表示
│   └── テーマ選択UI
└── 管理者（管理者のみ表示）
    └── 🔔 通知送信UI
```

- テーマ設定・通知送信の個別メニューはサイドバーから削除し、「設定」画面内に集約
- サイドバーは「設定」1項目のみに整理

## 認証フロー（変更点）

### 初回ログイン時（変更なし）

```
ログイン → password_changed_at が NULL
  → PasswordChangeModal 表示（既存のまま）
  → 「今すぐ変更」→ PasswordChangeForm → PasswordSuccessModal → JimuShift
  → 「後で変更」→ メイン画面
```

### 任意タイミングでの変更（新規）

```
設定画面を開く
  → パスワードセクションにフォームが表示されている
  → 入力・送信
  → 成功メッセージをインライン表示 + フォームリセット（画面遷移なし）
```

## バリデーション

既存の `usePasswordChange` フックのバリデーションをそのまま適用する。

| チェック | エラーメッセージ |
|---------|----------------|
| 現在のパスワード空欄 | "現在のパスワードを入力してください" |
| 新しいパスワード空欄 | "新しいパスワードを入力してください" |
| 新しいパスワード8文字未満 | "パスワードは8文字以上で設定してください" |
| 確認用パスワード不一致 | "パスワードが一致しません" |
| 現在のパスワードと同じ | "現在のパスワードと異なるパスワードを設定してください" |
| 現在のパスワードが誤り | "現在のパスワードが正しくありません" |
| Supabase APIエラー | "パスワードの更新に失敗しました。もう一度お試しください。" |
| ネットワークエラー | "ネットワークエラーが発生しました。接続を確認してください。" |

## API設計

### 使用する既存API

新規のAPIやEdge Functionは不要。既存のサービスを再利用する。

| API | 用途 | ファイル |
|-----|------|---------|
| `verifyCurrentPassword(email, password)` | 現在のパスワード検証 | `passwordService.js` |
| `changePassword(userId, newPassword)` | パスワード更新 + `password_changed_at` 更新 | `passwordService.js` |

---

## データベース設計

### スキーマ変更: なし

既存の `user_profiles.password_changed_at` カラムをそのまま使用する。パスワード変更時に現在時刻で更新される動作は変わらない。

## 実装の流れ

### フェーズ1: セクションコンポーネントの作成

1. `SettingsSection.jsx` — セクションヘッダー（ラベル + 区切り線）の汎用コンポーネント
2. `SettingsPasswordSection.jsx` — パスワード変更フォームを持つセクション
   - 既存の `usePasswordChange` フックを再利用
   - 既存の `passwordService.js` を再利用
   - 成功時は画面遷移せず、セクション内に成功メッセージを表示してフォームをリセット
3. `SettingsThemeSection.jsx` — テーマ選択UIを持つセクション
   - 既存の `ThemeOptionRow.jsx` を内包

### フェーズ2: 設定画面の組み立て

1. `SettingsScreen.jsx` — ScrollView + 各セクションを縦並びで配置
2. `DrawerNavigator.jsx` に `SettingsScreen` を登録
3. `usePasswordChange.js` の成功時コールバックを柔軟化（遷移ロジックを外部から渡せるように）

### フェーズ3: サイドバーの整理

1. `CustomDrawerContent.jsx` でテーマ設定・通知送信の個別メニューを削除
2. 「設定」（`SettingsScreen`）への1リンクに集約

### フェーズ4: テスト

1. 設定画面のスクロール表示確認（全セクションが1画面に表示されること）
2. 管理者セクションの表示切り替え確認（一般ユーザーには非表示）
3. パスワード変更の動作確認（成功時のインライン表示 / 各エラーケース）
4. テーマ設定の即時反映確認
5. 初回ログインフローが従来通り動作すること（退行テスト）
6. レスポンシブ対応（PC / スマホ表示）

## 影響範囲

| 対象 | 影響 |
|------|------|
| 初回ログインフロー | **変更なし**（既存のモーダルフローを維持） |
| テーマ設定機能 | 設定画面内のセクションに統合（`SettingsThemeScreen` は将来的に不要） |
| 管理者通知送信 | 設定画面内の管理者セクションに統合 |
| サイドバー | 設定セクションがシンプルになる |

---

## セキュリティ考慮事項

- パスワード変更時の現在パスワード検証は既存の `verifyCurrentPassword` で本人確認を行う
- パスワードはフロントエンドに保存しない（Supabase Auth が bcrypt でハッシュ化）
- パスワード変更後、セッションは維持（Supabase が新トークンを自動発行）
- 設定画面自体は認証済みユーザーのみアクセス可能（既存の認証フロー内）
