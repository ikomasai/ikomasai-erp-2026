## プロジェクト概要

### 目的

厚生部内のシフト運用では、誰がどこにいるか分からなくなることが課題となっていた。  
この機能では、厚生部がシフトで使用する場所をマップ上で管理し、各メンバーが現在いる場所を登録できるようにすることで、厚生部全体が配置状況を把握しやすくする。

### 対象画面

- Item6
- 画面表示名: `厚生部場所管理`

### スケジュール

- 開発開始: 2026/04/01
- リリース予定: 未定

---

## 対象ユーザー

### 厚生部員

- **いつ使うか:** シフト当日、配置場所に到着したとき
- **どういうときに使うか:** 自分がいる場所を選んで登録し、現在地を共有したいとき

### 厚生部長

- **いつ使うか:** シフト期間中の随時
- **どういうときに使うか:** シフト場所の追加・削除・更新を行い、厚生部員の現在地を確認したいとき

### 管理者

- **いつ使うか:** 運用確認時
- **どういうときに使うか:** 厚生部の場所管理機能を閲覧し、必要に応じて確認したいとき

## 機能要件

### 1. 場所管理機能

**概要:**
厚生部員が場所を登録できる。厚生部長が場所を更新・削除できる。

**詳細仕様:**

- 場所名、補足説明、表示順、緯度、経度を登録できる。
- 登録者名の表示人数を場所ごとに指定できる。
- 場所はマップ上でピンを指定して登録する。
- 編集時は登録済みの場所を選択し、内容を更新できる。
- 削除は論理削除とし、過去履歴は保持する。
- 削除済みの場所は一覧上で区別して表示する。

### 2. 現在地登録機能

**概要:**
厚生部員本人が、現在いる場所を一覧から選んで登録できる。

**詳細仕様:**

- 登録可能な場所は有効な場所のみとする。
- 登録後、選択した場所がマップ上に表示される。
- 現在地登録は上書き式とし、最新状態を保持する。
- 登録内容は履歴として保存する。

### 3. ステータス管理機能

**概要:**
厚生部員が自分の現在の活動状態を登録できる。厚生部長は各メンバーの状態を把握できる。

**詳細仕様:**

- 以下の3つのステータスを選択できる。
  - **配置中**: 特定の場所に配置されている。場所の選択が必要。
  - **巡回中**: 複数の場所を移動中。場所の選択は不要。
  - **離席中**: 一時的に持ち場を離れている。場所の選択は不要。
- ステータス変更は履歴として保存する。
- 巡回中・離席中のメンバーはマップ上にはピンを表示せず、現在地一覧でステータスとして表示する。
- デフォルトのステータスは「配置中」とする。

### 4. 現在地確認機能

**概要:**
厚生部長および管理者が、厚生部員の現在地を一覧とマップで確認できる。

**詳細仕様:**

- メンバー名、登録場所、更新日時を表示する。
- 現在地はリアルタイム更新に対応する。
- 最新状態と履歴を両方参照できる。

### 5. 閲覧権限制御

**概要:**
厚生部または管理者だけが機能を閲覧できる。

**詳細仕様:**

- 閲覧対象は `厚生部` ロール、または `管理者` ロール所持者。
- 場所の登録は `厚生部` ロール所持者。
- 場所の更新・削除は `厚生部` と `部長` の両方を持つ厚生部長のみ。
- 現在地登録は厚生部員本人のみ。

## 画面設計

### 1. 厚生部場所管理画面

**画面名:** 厚生部場所管理  
**ルート名:** `Item6`

**表示項目:**

- 概要カード
- 現在選択中の場所
- マップ表示
- 自分の場所登録フォーム
- 現在地一覧
- 場所登録フォーム
- 場所一覧
- 登録履歴

**動作:**

1. 画面表示時に場所一覧、現在地、履歴を読み込む
2. 厚生部員は場所を選択して現在地を登録する
3. 登録ボタンを押下すると現在地が保存される
4. 厚生部員はマップ上でピンを指定して場所を登録できる
5. 厚生部長は場所を更新・削除できる
6. 変更内容はリアルタイムで反映される

## データベース設計

### テーブル一覧

| テーブル名 | 説明 |
| ---------- | ---- |
| `koseibu_shift_locations` | 厚生部シフトで使用する場所情報 |
| `koseibu_shift_current_locations` | 厚生部メンバーの現在地 |
| `koseibu_shift_location_logs` | 厚生部場所の操作履歴 |

### koseibu_shift_locations テーブル

**説明:** 厚生部が使用する場所情報を管理する。

| カラム名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| id | uuid | PK | 場所ID |
| name | text | NOT NULL | 場所名 |
| latitude | double precision | NOT NULL | 緯度 |
| longitude | double precision | NOT NULL | 経度 |
| description | text | NULL | 補足説明 |
| display_member_count | integer | NOT NULL, DEFAULT 3 | 表示する登録者名の人数（0で非表示） |
| display_order | integer | NOT NULL, DEFAULT 0 | 表示順 |
| is_active | boolean | NOT NULL, DEFAULT true | 有効フラグ |
| created_by | uuid | FK | 登録者 |
| created_at | timestamptz | NOT NULL | 作成日時 |
| updated_at | timestamptz | NOT NULL | 更新日時 |

**リレーション:**

- `created_by` -> `auth.users.id`

### koseibu_shift_current_locations テーブル

**説明:** 厚生部員の最新現在地を管理する。

| カラム名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| id | uuid | PK | レコードID |
| user_id | uuid | UNIQUE, NOT NULL | 厚生部員ID |
| status | text | NOT NULL, DEFAULT 'stationed' | ステータス（stationed/patrolling/away） |
| location_id | uuid | NULL | 場所ID |
| location_name_snapshot | text | NULL | 登録時点の場所名 |
| latitude_snapshot | double precision | NULL | 登録時点の緯度 |
| longitude_snapshot | double precision | NULL | 登録時点の経度 |
| updated_by | uuid | NOT NULL | 更新者 |
| updated_at | timestamptz | NOT NULL | 更新日時 |
| created_at | timestamptz | NOT NULL | 作成日時 |

**リレーション:**

- `user_id` -> `auth.users.id`
- `location_id` -> `koseibu_shift_locations.id`
- `updated_by` -> `auth.users.id`

### koseibu_shift_location_logs テーブル

**説明:** 場所登録・更新・削除・現在地登録の履歴を保存する。

| カラム名 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| id | uuid | PK | 履歴ID |
| user_id | uuid | NULL | 対象ユーザーID |
| location_id | uuid | NULL | 対象場所ID |
| location_name_snapshot | text | NOT NULL | 操作時点の場所名 |
| latitude_snapshot | double precision | NULL | 操作時点の緯度 |
| longitude_snapshot | double precision | NULL | 操作時点の経度 |
| action_type | text | NOT NULL | 操作種別 |
| operated_by | uuid | NOT NULL | 操作者 |
| memo | text | NULL | 補足 |
| created_at | timestamptz | NOT NULL | 作成日時 |

**操作種別:**

- `create`
- `update`
- `delete`
- `self_register`

**リレーション:**

- `user_id` -> `auth.users.id`
- `location_id` -> `koseibu_shift_locations.id`
- `operated_by` -> `auth.users.id`

## 非機能要件

### パフォーマンス

- 画面表示は 3 秒以内を目標とする。
- 登録操作は 1 秒台で完了することを目標とする。

### 可用性

- 厚生部の運用時間帯に安定して利用できること。

### スケーラビリティ

- 厚生部員 50 人程度の同時利用を想定する。
- 履歴件数が増えても最新状態の取得が遅くならないようにする。

### 対応環境

- Web
- iOS
- Android

## セキュリティ設計

### 認証・認可

- `厚生部` または `管理者` のみ閲覧可能。
- 場所の登録は厚生部員が可能。
- 場所の更新・削除は厚生部長のみ可能。
- 現在地登録は厚生部員本人のみ。

### データ保護

- RLS を有効化する。
- 操作履歴を残し、誰が何を行ったか追跡できるようにする。
- 通信は HTTPS を前提とする。

## Supabase 使用量見積もり

厚生部員 50 人を想定した場合の目安。

- リアルタイムメッセージ: 約 `1,000 件 / イベント期間`
- エッジ関数: `0 件`
- 帯域: 約 `0.05 GB / イベント期間`
- データベース量: 約 `0.01 GB`
- 同時接続数: 最大 `50 接続程度`

前提:

- 1 人あたり 1 日 1〜2 回の現在地登録
- 場所情報は数十件程度
- 閲覧は常時 10 人前後を想定
